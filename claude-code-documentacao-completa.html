01O que é o Claude Code?

Entenda a ferramenta antes de decorar comandos.

O Claude Code é a ferramenta de linha de comando (CLI) da Anthropic que coloca o Claude — o modelo de IA — dentro do seu terminal, com acesso direto aos arquivos do seu projeto. Diferente de um chat comum, ele consegue:

📖Ler e entender seu código

Ele explora o repositório sozinho: abre arquivos, entende a arquitetura e o contexto do projeto sem que você precise copiar e colar nada.

✏️Editar arquivos de verdade

Cria, modifica e refatora arquivos diretamente no disco. Você aprova (ou não) cada alteração antes de ela acontecer.

⚙️Executar comandos

Roda testes, builds, git, scripts e qualquer comando de terminal — e corrige o que falhar, em ciclo, até funcionar.

🤖Trabalhar em paralelo

Delega tarefas para subagentes, roda em segundo plano e orquestra mudanças grandes no código inteiro de uma vez.

Analogia para leigos Pense no Claude Code como um desenvolvedor sênior contratado que trabalha dentro do seu terminal. Você conversa com ele em português normal ("corrija o bug de login", "crie um relatório em PDF"), e ele faz o trabalho. Os comandos de barra (que começam com /) são os "botões de controle" desse funcionário: trocar de modelo, limpar a conversa, revisar código, etc.

Três camadas de controle

Existem três formas de comandar o Claude Code, e cada uma serve para um momento diferente:

CamadaQuando usarExemplo
Flags de CLIAntes de iniciar a sessão, no terminalclaude --model opus
Comandos de barraDentro de uma sessão ativa/compact, /model, /plan
Linguagem naturalPara o trabalho em si"refatore o módulo de autenticação"

02Instalação e primeiro uso

Do zero a uma sessão funcionando em 3 minutos.

Requisitos

  • Node.js 18 ou superior instalado (verifique com node -v)
  • Uma conta Anthropic — assinatura Claude Pro/Max ou chave de API da plataforma
  • Windows, macOS ou Linux (no Windows, funciona nativamente ou via WSL)
Terminal — Instalação
# 1. Instalar globalmente via npm
npm install -g @anthropic-ai/claude-code

# 2. Entrar na pasta do seu projeto
cd ~/projetos/meu-projeto

# 3. Iniciar o Claude Code
claude

# Na primeira vez, ele abrirá o navegador para você fazer login (/login)
Dica de ouro para o primeiro dia Assim que iniciar o Claude Code num projeto pela primeira vez, rode /init. Ele analisa o projeto e cria o arquivo CLAUDE.md — a "memória permanente" do projeto. Depois rode /permissions para definir o que ele pode fazer sem pedir permissão. Esses dois comandos economizam horas nas semanas seguintes.

Verificando se está tudo certo

Dentro do Claude Code
/doctor
# Diagnostica a instalação. Se algo estiver errado,
# pressione a tecla "f" e o próprio Claude corrige o problema.

/status
# Mostra versão, modelo ativo, conta logada e conectividade

Exemplo real — automação em script
# Gerar resumo diário do git log sem abrir sessão interativa:
git log --since=yesterday --oneline | claude -p "Resuma essas alterações em português para o relatório diário da equipe"

# Retomar o trabalho de ontem exatamente de onde parou:
claude -c

04Os 10 comandos essenciais

Se você aprender só isto, já resolve 90% do dia a dia.

1. /init — Criar a memória do projeto

Analisa seu projeto e gera o CLAUDE.md, o arquivo que ensina ao Claude as convenções, a stack e os comandos do seu projeto. Rode uma vez em cada projeto novo.

Sessão
/init
✓ CLAUDE.md criado com: stack do projeto, comandos de build/teste e convenções detectadas

2. /plan — Pensar antes de agir

Entra no modo de planejamento: o Claude explica exatamente o que pretende fazer — quais arquivos vai tocar e por quê — antes de alterar uma linha sequer. Indispensável para mudanças grandes.

Sessão
/plan corrigir o bug de autenticação no login
# Claude apresenta o plano → você aprova → só então ele executa

3. /compact — Liberar espaço na conversa

Sessões longas enchem a "memória de curto prazo" (janela de contexto). O /compact resume a conversa preservando o essencial. Use quando o contexto passar de ~80% (veja com /context).

Sessão
/compact foque no módulo de pagamentos e nos testes que estão falhando

4. /clear — Começar tarefa nova do zero

Zera a conversa (mas mantém o CLAUDE.md e a memória do projeto). A conversa anterior fica salva e pode ser recuperada com /resume. Aliases: /reset, /new.

5. /model e /effort — Controlar o cérebro

/model troca o modelo (Opus para tarefas difíceis, Sonnet para o dia a dia, Haiku para tarefas rápidas). /effort ajusta a profundidade de raciocínio: low, medium, high, xhigh, max.

6. /code-review — Revisar antes de enviar

Revisa o diff atual em busca de bugs de correção e oportunidades de limpeza. Com --fix aplica as correções automaticamente; ultra roda uma revisão profunda multi-agente na nuvem.

Sessão
/code-review high
/code-review --fix        # encontra E corrige
/code-review ultra        # revisão profunda na nuvem

7. /rewind — O botão de desfazer

Volta o código e a conversa para um ponto anterior (checkpoint). Errou? Volte no tempo. Aliases: /undo, /checkpoint.

8. /resume e /branch — Navegar entre sessões

/resume abre o seletor de conversas antigas. /branch cria uma ramificação da conversa atual — como um "git branch" da conversa — para testar outra abordagem sem perder a atual.

9. /usage — Controlar custo e limites

Mostra custo da sessão, limites do plano e estatísticas de uso por skill, subagente e servidor MCP. Aliases: /cost, /stats.

10. /permissions — Definir a confiança

Gerencia o que o Claude pode fazer sem perguntar (allow), o que sempre pergunta (ask) e o que é proibido (deny). Alias: /allowed-tools.

Sequência mínima para iniciantes /init → /permissions → /plan sua tarefa → trabalhar → /code-review --fix → /clear para a próxima tarefa. Só isso já é um fluxo profissional.

07Skills: crie seus próprios comandos

Transforme qualquer prompt repetitivo num comando de barra reutilizável.

Qualquer instrução que você digita com frequência pode virar um comando. O formato recomendado hoje são as skills: pastas com um arquivo SKILL.md contendo instruções. O formato antigo (.claude/commands/*.md) continua funcionando, mas skills são superiores porque o Claude também pode invocá-las sozinho quando percebe que são relevantes, e podem incluir scripts e arquivos de apoio.

Criando sua primeira skill em 60 segundos

Terminal
# 1. Criar a pasta da skill dentro do projeto
mkdir -p .claude/skills/revisar-seguranca

# 2. Criar o arquivo SKILL.md
cat > .claude/skills/revisar-seguranca/SKILL.md << 'EOF'
---
name: revisar-seguranca
description: Revisa o código em busca de vulnerabilidades de segurança
allowed-tools: Read, Grep, Glob
---

Analise o código-alvo em busca de vulnerabilidades:
- Riscos de SQL injection
- Vulnerabilidades XSS
- Credenciais expostas no código
- Configurações inseguras

Alvo da análise: $ARGUMENTS

Apresente os achados em ordem de severidade (Crítico → Baixo),
com o arquivo, a linha e a correção sugerida para cada um.
EOF

# 3. Dentro do Claude Code, recarregue e use:
/reload-skills
/revisar-seguranca src/api/

Recursos do frontmatter (o cabeçalho YAML)

CampoPara que serve
name / descriptionNome do comando e descrição — a descrição ajuda o Claude a invocar a skill automaticamente quando apropriado
allowed-toolsRestringe as ferramentas que a skill pode usar. Ex.: Read, Grep, Bash(git diff *)
argument-hintDica de argumentos exibida no autocompletar. Ex.: [padrão-de-teste]
modelForça um modelo específico para a skill (ex.: haiku para tarefas simples e baratas)
$ARGUMENTS, $1, $2No corpo: $ARGUMENTS captura tudo que vem após o comando; $1, $2 capturam argumentos posicionais
!`comando`No corpo: executa um comando bash e injeta a saída no prompt. Ex.: !`git diff HEAD~1`
Onde salvar Skill do projeto (compartilhada com a equipe via git): .claude/skills/nome/SKILL.md — Skill pessoal (disponível em todos os seus projetos): ~/.claude/skills/nome/SKILL.md. Se uma skill e um comando antigo tiverem o mesmo nome, a skill vence.

08O arquivo CLAUDE.md

O arquivo mais importante de todo o sistema.

Ao iniciar uma sessão, a primeira coisa que o Claude Code lê é o CLAUDE.md — e ele mantém essas instruções em mente durante toda a conversa. É a memória permanente do projeto. Um bom CLAUDE.md cobre cinco coisas:

CLAUDE.md — exemplo real e enxuto
# Projeto: API de Gestão de Chamados

## Stack
- Python 3.12 + FastAPI + PostgreSQL
- Frontend: Streamlit
- Testes: pytest

## Comandos
# O Claude executa ESTES comandos em vez de adivinhar:
- Rodar em dev:  uvicorn app.main:app --reload
- Testes:        pytest -v
- Lint:          ruff check .

## Arquitetura
- app/routers/  → rotas da API (sem lógica de negócio aqui!)
- app/services/ → lógica de negócio
- app/models/   → modelos SQLAlchemy

## Convenções
- Toda função pública tem docstring em português
- Nunca usar print(); usar o logger do módulo app.core.log
- Commits em português, no padrão Conventional Commits

## Regras críticas
- NUNCA commitar segredos, chaves ou tokens
- Toda query ao banco usa parâmetros (nunca f-string)

✅O que colocar

Comandos de build/teste (evita o Claude adivinhar errado), mapa da arquitetura, convenções que não dá para inferir do código, regras não-negociáveis.

❌O que NÃO colocar

Coisas que o Claude aprende sozinho na primeira sessão (a auto-memória registra), documentação longa (use .claude/rules/), e informações desatualizadas — um CLAUDE.md errado é pior que nenhum.

Hierarquia de memória

Existem vários níveis de CLAUDE.md, e o mais específico vence em caso de conflito:

1. Global~/.claude/CLAUDE.md
Suas preferências pessoais, em todos os projetos
2. Projeto./CLAUDE.md
Regras da equipe, commitado no git
3. LocalCLAUDE.local.md
Seus ajustes pessoais no projeto (fora do git)
4. Subpastassrc/api/CLAUDE.md
Carregado sob demanda ao trabalhar naquela pasta
Auto-memória Desde a v2.1.59, o Claude Code mantém uma auto-memória por projeto: ele anota sozinho comandos que descobre, padrões que observa e aprendizados, e relê nas próximas sessões. Gerencie tudo com /memory. É local à sua máquina — não vai para o git nem para a equipe.

09Estrutura de diretórios ideal ★

A resposta oficial para "como organizar tudo isso?"

Existem duas pastas .claude, e entender a diferença resolve 90% da confusão:

📁.claude/ no projeto

Configuração da equipe. Vai para o git. Todos que clonarem o repositório herdam as mesmas regras, skills, permissões e subagentes.

🏠~/.claude/ na home

Configuração pessoal. Suas preferências e estado local (histórico, auto-memória), aplicados a todos os seus projetos. No Windows: %USERPROFILE%\.claude.

Estrutura recomendada — nível projeto

Nem toda pasta precisa existir: o Claude Code as cria sob demanda. Esta é a anatomia de um projeto maduro:

meu-projeto/ ├── CLAUDE.md # ★ Memória do projeto (commitado — regras da equipe) ├── CLAUDE.local.md # Suas anotações pessoais (adicione ao .gitignore) ├── .mcp.json # Servidores MCP do projeto (commitado) │ ├── .claude/ │ ├── settings.json # ★ Permissões, hooks e config da equipe (commitado) │ ├── settings.local.json # Suas exceções pessoais (gitignored) │ │ │ ├── rules/ # Instruções modulares por tema (carregadas sempre) │ │ ├── estilo-codigo.md │ │ ├── testes.md │ │ └── seguranca.md │ │ │ ├── skills/ # ★ Seus comandos personalizados (formato atual) │ │ ├── revisar-seguranca/ │ │ │ └── SKILL.md # → vira o comando /revisar-seguranca │ │ └── gerar-relatorio/ │ │ ├── SKILL.md │ │ └── scripts/ # Skills podem incluir scripts de apoio │ │ │ ├── agents/ # Subagentes especializados │ │ ├── revisor-codigo.md │ │ └── auditor-seguranca.md │ │ │ ├── hooks/ # Scripts disparados em eventos (registrados no settings.json) │ │ └── bloquear-segredos.sh │ │ │ └── commands/ # Formato legado de comandos (ainda funciona; prefira skills/) │ └── src/ └── api/ └── CLAUDE.md # Opcional: regras específicas, carregadas sob demanda

Estrutura global — ~/.claude/

~/.claude/ ├── CLAUDE.md # Suas preferências globais (carregado em TODA sessão) ├── settings.json # Configurações globais — NÃO delete (guarda auth e prefs) ├── history.jsonl # Histórico de prompts de todas as sessões │ ├── skills/ # Skills pessoais, disponíveis em todos os projetos ├── agents/ # Subagentes pessoais ├── rules/ # Regras pessoais (projeto tem prioridade em conflito) ├── themes/ # Temas de cores personalizados (/theme) │ ├── projects/ # Transcripts de sessão + auto-memória, por projeto ├── plans/ # Documentos do modo de planejamento ├── file-history/ # Checkpoints de arquivos (é o que permite o /rewind) ├── todos/ # Listas de tarefas por sessão └── plugins/ # Plugins instalados — NÃO delete
Ordem de precedência (quem vence em conflito) 1. Configurações gerenciadas pela organização (empresa) → 2. Flags de CLI da sessão (--permission-mode) → 3. settings.local.json do projeto → 4. settings.json do projeto → 5. ~/.claude/settings.json global. Regra prática: o mais específico vence.

Checklist para montar do zero

  1. Na raiz do projeto, rode claude e depois /init → gera o CLAUDE.md
  2. Rode /memory e refine o arquivo: comandos reais de build/teste, arquitetura, convenções
  3. Rode /permissions e defina as regras de confiança (ou /fewer-permission-prompts depois de alguns dias de uso)
  4. Crie .claude/skills/ para os fluxos que você repete (relatórios, revisões, deploys)
  5. Adicione ao .gitignore: CLAUDE.local.md e .claude/settings.local.json
  6. Commite o resto de .claude/ e o CLAUDE.md — sua equipe herda tudo
Script — criar a estrutura de uma vez
# Execute na raiz do projeto:
mkdir -p .claude/{skills,agents,rules,hooks}
touch CLAUDE.md .claude/settings.json
echo -e "CLAUDE.local.md\n.claude/settings.local.json" >> .gitignore
# Depois abra o Claude Code e rode /init para preencher o CLAUDE.md

12Dicas de especialista

O que separa quem usa de quem domina.

🧠Contexto é ouro

Monitore com /context e compacte com /compact antes de atingir o limite (ideal: aos ~80%). Passe instruções de foco: /compact foque no módulo X. Para tarefa nova, prefira /clear.

📋Plan mode para tudo que é grande

Mudanças em 3+ arquivos? /plan primeiro. Custa 30 segundos e evita retrabalho. Alterne rápido com Shift+Tab.

💰Modelo certo para a tarefa certa

Opus/Fable para arquitetura e problemas difíceis; Sonnet para o dia a dia; Haiku para tarefas mecânicas. /usage mostra onde seu orçamento está indo — inclusive por skill e MCP.

🔁Se você digitou 3 vezes, vire skill

Qualquer prompt repetido é candidato a .claude/skills/. Commite no git e a equipe inteira ganha o comando.

⏪Confie no /rewind

O Claude Code cria checkpoints automáticos dos arquivos. Experimente sem medo: /rewind volta código e conversa. É o "ctrl+z do universo".

🪝Hooks para o que é obrigatório

Prompt "sugere"; hook "garante". Lint após cada edição, bloqueio de segredos antes de commit — isso vai em /hooks, não no CLAUDE.md.

🏷️Nomeie suas sessões

/rename fix-auth-bug hoje = achar em 2 segundos com /resume daqui a 3 semanas. Sem nome, é uma lista de timestamps indecifráveis.

🧪/verify > "os testes passaram"

Testes verdes não significam que funciona. /verify compila, executa e observa o app rodando de verdade. Configure uma vez com /run-skill-generator.

Verdades que ninguém te conta Comandos de barra consomem tokens — não são atalhos gratuitos (até o /compact tem custo). Comandos personalizados rodam no contexto atual, não numa sessão limpa. E bibliotecas de comandos da comunidade são código de terceiros rodando no seu ambiente — revise antes de confiar.
